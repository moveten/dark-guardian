v0.6.4.0503  (11/04)  랭킹 DB에 클리어 횟수(cc) · 하드코어 탭 이동·순서 변경
==============================
■ 랭킹 데이터
  - 추가: dd_rank 의 data 에 cc 추가 = '가장 높이 클리어한 스테이지의 클리어 횟수' (캐릭터에 이미 집계 중이던 스테이지별 누적 클리어 횟수 중 최고 스테이지 값, 클리어 기록이 없으면 생략). 랭킹 목록도 cc 를 함께 받아 옴(가벼운 목록 조회에 data->cc 추가)
■ 랭킹 탭 (관리자 2번째 줄)
  - 변경: [⏰ 최근활동] [📈 미사용1] [💀 하드코어] — 미사용2 삭제, 하드코어 탭을 첫 줄에서 이곳으로 이동 (첫 줄은 다시 레벨·타임어택·진행 3개)
  - 변경: 하드코어 순서 — 높은 스테이지(클리어 수) → 레벨 → 클리어 횟수(cc) 많은 순 (모두 같으면 처치 수). 이전: 스테이지 → 처치 수 → 레벨
  - 변경: 하드코어 줄 아래 글자 — 'Lv 40 · 클리어 7회' / 사망: '💀 1-3에서 사망 · 클리어 2회' (처치 수 표기 제거)
  - 참고: 하드코어 조회용 DB 인덱스(dd_rank_hc_idx)는 옛 순서(스테이지·처치·레벨) 그대로 둠 — 데이터가 적어 순위 계산은 앱에서 하므로 영향 없음

v0.6.4.0500  (11/04)  하드코어 모드 (관리자 전용)
==============================
■ 공개 범위
  - 관리자 권한(연구실)이 켜진 계정에서만 [캐릭터 생성 체크]와 [💀 하드코어 랭킹 탭]이 보임. 이미 만들어진 하드코어 캐릭터의 규칙(사망·창고 차단)은 권한과 상관없이 항상 적용
■ 캐릭터 만들기
  - 추가: 닉네임 입력창에 '💀 하드코어 캐릭터' 체크 카드 (체크하면 버튼이 '💀 만들기'로 바뀜). 일반 캐릭터와 시스템은 완전히 같고 아래 규칙만 다름
  - 하드코어는 일반으로 바꿀 수 없음
  - 캐릭터 카드 왼쪽 위에 '🔥 하드코어' 리본, 사망하면 '💀 사망' 리본 + 흑백 처리
■ 사망 규칙
  - 부활 전부 없음: 무료 부활물약(스테이지 시작 시 1회)·부활물약·동료 구조 모두 불가. 쓰러지는 즉시 사망 확정 (HUD 부활 버튼 숨김, 상점 부활 물약 행 숨김, R키·자동 사냥의 부활 동작도 무시)
  - 사망 순간 캐릭터 데이터에 즉시 저장(hd=사망 시각, hs=사망한 스테이지 번호) → 앱을 바로 꺼도 사망 유지. 랭킹에도 곧바로 💀 로 올림
  - 전체 화면 'YOU DIED' 화면 → [확인]을 누르면 타이틀로. 혼자 하기에서는 일반 '쓰러졌습니다' 결과창 대신 이 화면만 나옴. 협동 중에는 동료가 계속 진행 가능
  - 죽은 캐릭터는 카드가 그대로 남지만 시작·상점·마을 사용 불가. 이름 변경도 막힘. 삭제만 가능
  - 죽은 상태에서도 [정비]를 누르면 장비·펫·능력치를 읽기 전용으로 볼 수 있음 (랭킹 프로필과 같은 화면)
  - 삭제하면 그 캐릭터의 도감과 랭킹 기록도 함께 사라짐 (도감은 캐릭터별 저장). 삭제하지 않으면 랭킹에 💀 로 계속 남음 (자동 삭제 없음)
■ 공유보관함 · 전달 차단
  - 공유보관함 이용 불가: 보관함 탭 비활성, 가방의 '📦 창고로' 숨김, 마을 조각 수확(보관함으로 이동) 불가, 골드·아이템·조각 보내기/받기 모두 불가
  - 다른 캐릭터와의 전달도 불가: 하드코어 캐릭터는 보낼 곳이 없음, 일반 캐릭터도 하드코어 캐릭터를 받는 곳으로 고를 수 없음. 마을 물약 우편은 자기 자신에게만 가능
  - 풍차·연구소 효과는 계정 공유 그대로. 단, 하드코어 캐릭터가 마을·연구소 비용을 낼 때는 자기 골드·조각만 사용 (보관함 골드·조각은 사용 안 됨)
■ 랭킹
  - 추가: 관리자에게만 랭킹 첫 줄에 4번째 탭 '💀 하드코어'. 순서: 높은 스테이지(클리어 수) → 처치 수 → 레벨. 타임어택 구조에서 클리어 시간 대신 처치 수를 비교
  - 죽은 캐릭터는 흐리게 + 이름 앞 💀 + '💀 1-3에서 사망 · 처치 200'. 이름을 누르면 장비/능력치 프로필에 '사망한 하드코어 캐릭터' 표시
  - 일반 랭킹(레벨·타임어택·진행)에서는 하드코어 캐릭터가 빠짐 (서버 조건 hc=is.false). 예전 버전 앱은 아직 일반 랭킹에 보일 수 있음. ⏰ 최근활동은 하드코어도 포함
  - DB: dd_rank 에 hc(boolean), dead_at(timestamptz) 컬럼과 인덱스 추가 — 적용 SQL은 supabase_rank_hc.sql
■ 알려진 한계
  - 클라우드 복구 코드로 예전 저장본을 불러오면 이미 사망 처리된 캐릭터가 되살아날 수 있음 (사망 시점 이후의 저장본을 불러온 경우에만 사망 유지)

v0.6.4.0499  (11/04)  연구실 · 출입 기록 · 랭킹 최근활동
==============================
■ 연구실 (관리자 전용 공간)
  - 추가: 상점의 구매창 아래에 '📚 연구실' 섹션 (활성화된 계정에서만 보임)
    · 문구: '어서오세요, 관리자님 환영합니다.'
    · 버튼: 📔 관리자 노트(이 파일 열람) / 📜 출입 기록(출입 기록 열람) / 🚪 나가기(관리자 권한 반납 = 연구실 비활성화, 확인창 한 번)
  - 활성화 방법: 장비 아이템 레벨 합이 0이고 캐릭터 Lv이 2인 캐릭터가, 상점에서 즉시 부활(부활물약)을 4개 구매하려다 골드가 모자라 '금화가 부족해요'가 뜰 때 관리자 비밀번호 창이 뜸 → 비밀번호(****) 입력 시 활성화
  - 적용 범위: 캐릭터별이 아니라 계정 전체 (저장 키 dkdef2.lab, 클라우드 저장에도 함께 저장되어 복구 코드로 이어받은 기기에서도 켜져 있음)
  - 비밀번호 확인: 입력값의 해시로만 비교(코드에 비밀번호 글자는 없음). 출입 기록 저장·열람은 서버(DB 함수)가 비밀번호를 한 번 더 확인
  - 비밀번호를 입력한 기기에만 비밀번호를 보관(dkdef2.cl.labpw, 클라우드 저장 제외). 복구 코드로 이어받은 기기에서는 출입 기록 열람·나가기 때 한 번 더 물어봄
■ 출입 기록 (charlogs.txt 형식)
  - 추가: 관리자 권한을 얻거나 반납하면 시간과 그 계정의 모든 캐릭터 이름을 기록
    · 획득: yyyy/MMM/dd(aaa) HH:mm:ss, 새로운 관리자가 권한을 획득하였습니다 - john, tom, jane
    · 반납: yyyy/MMM/dd(aaa) HH:mm:ss, john, tom, jane 이 관리자 권한을 반납했습니다.
    · (aaa)는 요일 한 글자(월·화·수…), MMM은 영문 월 약어(Nov)
  - 저장 위치: 정적 파일(txt)은 게임이 직접 쓸 수 없어서 서버 테이블 dd_charlog 에 쌓고, [📜 출입 기록]에서 위 형식 그대로 최신순으로 보여줌. 저장소의 charlogs.txt 로 내보내려면 요청 (현재 저장소에는 파일 없음)
  - 서버 연결이 안 되면 기기에 대기열(dkdef2.cl.labq, 최대 20건)로 남겨 뒀다가 다음에 다시 보냄. 열람 화면에는 '(전송 대기)'로 표시
  - DB: 테이블 dd_charlog(id, kind in/out, names, created_at) — 앱에서 직접 읽기/쓰기 불가(RLS), 함수 dd_lab_log(비밀번호, 종류, 이름들, 시각) / dd_lab_list(비밀번호, 개수)로만 접근. 생성 SQL은 supabase_charlog.sql (비밀번호는 ****)
■ 랭킹
  - 추가: 관리자 권한이 있으면 랭킹 탭 아래에 한 줄 더 표시 [⏰ 최근활동] [📈 미사용1] [📈 미사용2] (미사용 두 칸은 눌려도 동작 없음, 자리만 잡아 둠)
  - 추가: ⏰ 최근활동 = 랭킹 DB(dd_rank)의 updated_at 이 최근인 캐릭터 순. 캐릭터 이름 아래에 updated_at(yyyy/MMM/dd(aaa) HH:mm:ss), 오른쪽 값(rkv)에는 캐릭터 레벨
  - 최근활동은 10분 캐시를 쓰지 않고 열 때마다 새로 불러옴
■ 기록 규칙
  - 관리자 관련 추가·수정, 치트키, 미공개(요청·스테이지·캐릭터 등) 내용은 patchnotes.txt 가 아니라 이 파일(adminnotes.txt)에 기록. 한 번의 요청에 둘이 섞여 있으면 나눠서 기록 (패치노트에는 '■ 기타 - 추가: 연구실 기능이 추가되었습니다.' 정도로만)
  - 이 파일의 비밀번호는 '****'로 표시
